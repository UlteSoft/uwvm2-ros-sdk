# PolyScope X SDK v0.11 scalar services

The versioned public header implements the historical `SetAnalogOutput`, `SetDigitalOutput` and `SetSpeedFraction` request builders, canonical codecs, one-attempt service calls, server request polling and responses in the calling Wasm Guest. It borrows the caller's capability. It opens no endpoint, supplies no grant and creates no thread, executor or retry. Callers serialize access and keep private live objects, the context and immutable backend alive throughout each call. A request ticket is not a capability; the runtime must check the real caller and separately granted service roles.

The [official v0.11 document](https://docs.universal-robots.com/PolyScopeX_SDK_Documentation/build/SDK-v0.11/_downloads/269b9c285239fcf0175c496d94007a2b/URInterfacesAPI.html) defines scalar analog `int8 pin`, `bool output_type`, `float64 value`; scalar digital `int8 pin`, `bool state`; speed `float32 value`; and a `bool success` response. Current mode uses the document's **0.002–0.020 amperes**, voltage mode **0–10 volts**, and speed **0–1**. The scalar API is separate from later `urinterfaces` array requests. The SDK canonical byte representation is not native ROS CDR or a native C struct ABI. The official document does not identify the complete source commit; matching native package/type-support custody remains required.

`main.c` provides four standard Xmake Guest cases: values (14 assertions), invalid (34), client (20) and server (20). The last two use a scripted backend inside the Guest to check exact dispatch bytes, false responses, invalid lengths/bools/tickets, unchanged destinations, unsupported dispatch, actual error propagation and no implicit replay. These 88 assertions are auxiliary facade contract tests. They do not count as official ROS roundtrips, runtime permission denials, private-memory isolation or Stage A/B acceptance. The range/overlap checks are local C preconditions, not an ACL or proof of live storage. `xmake test` uses the existing real VM component-test entry, which requires an independently qualified public boundary and pinned runtime deployment.

`live_client.c` instead calls the actual ROS2 imports. Its syntax is `analog ALIAS PIN current|voltage VALUE`, `digital ALIAS PIN STATE`, or `speed ALIAS FRACTION`. It validates before opening, attempts the real service exactly once and closes its owned handle once. The alias must already bind this caller to the exact historical scalar type. The JSON reports actual transport and close errors separately; a valid `success=false` remains transport success and produces process exit 1. No real service case is runnable until the matching native type support, restricted host mapping, official peer and caller-bound grant have been qualified. No support enum is enabled by this source.

Build and test only on SSH Linux under the current admission, whole-source hash verification, exact subject's own lifecycle proof, canonical lease and original capacity reserves. The authored sources and cases have not yet been compiled or executed. Once the shared public boundary and historical native binding are qualified, retain all three positive and negative real service families, fresh feedback, revocation/cross-instance/type/bounds denials and the full earlier Stage A/B denominator. The scripted cases cannot replace them.
