# Independent planner and actuator source

These are new C1 application sources, not compiled or executed artifacts. They do not qualify memory isolation or reuse the original C0 hash. First qualify the parent example's real official ROS Stage A; then build these sources on admitted SSH Linux with the installed SDK. `xmake` declares a real planner static archive and two real Wasm commands. The mandatory `xmake test` integration entry currently fails before VM launch because the common multi-instance deployment/channel binding has not been qualified. Source or build success cannot pass that entry.

The planner owns its C heap and links planner_kernel.c into the same instance. Ordinary pointers passed to that static algorithm stay inside this one trust domain. The algorithm validates every bound before computing a single bounded joint step and commits its output only after all inputs are valid. The planner must have no ROS grant: it actually calls the existing portable `open` and requires permission error13 with an unchanged output slot.

The actuator owns a different C heap and the narrow existing bounded-joint ROS grant. It receives the real descriptor and fresh state through the existing SDK ABI, copies a bounded snapshot to the planner, validates the returned plan against that snapshot, and submits once. It checks the accepted/terminal receipts and actual fresh post-result positions inside Wasm, closes its acquired ROS handle once, and returns the result/state copy to the planner. The planner independently checks the terminal epoch, sequence, fresh time window and every returned target position. Native application planning, publishing, result consumption or invented feedback is absent.

component_stream.h defines application records only. Its existing WASIp1 FD3/FD4 operations require exact nonblocking read or write rights, no inheritable rights, bounded copies and finite waits. The future VM/SDK01 adapter must explicitly bind each instance's private descriptor namespace to authenticated, generation-bound typed host-copy channels. These numeric FDs, record fields, module hashes and descriptive component names confer no authority. No component handle, private pointer, memory index or grant is sent to a peer. Channel identity/generation, immutable copy snapshots and caller ownership must be enforced and audited by the real runtime; this source does not implement a second common ABI.

The private memories must be distinct backing objects. Each binary must define its own unshared memory; neither private heap may be imported by the peer. The planner's static archive deliberately shares the planner heap and authority. Pointer-sharing preload mode remains an explicit separate compatibility mode and is not used here. Same offsets, different names or multiple local memory indices alone prove no separation.

Launch the actual planner and observe its bounded await-snapshot phase before obtaining the actuator's first fresh state. Both guests require the runtime's monotonic clock to use the state timestamps' verified clock domain; snapshots older than250ms are rejected before submit. The runtime must preserve all eight-poll bounds and enforce channel capacity/backpressure. A deadline or transport error never replays a command. A trapped or retired peer cannot grant access or turn an old result into a new success.

required-isolation.json retains the six negative-case families and the earlier ten first-slice cases, all NOT_RUN. memory-graph.json is an intended binding graph, not an observed runtime graph. Each emitted Wasm, archive, compiler/sysroot/ABI identity and actual instance/memory/channel/grant graph must be frozen after a genuine build, then exercised through the public commands with complete actor/lease/unwind evidence. The later sensor/reader extension, all original language/architecture/security/update/performance cases and full vendor Stage B remain mandatory.
