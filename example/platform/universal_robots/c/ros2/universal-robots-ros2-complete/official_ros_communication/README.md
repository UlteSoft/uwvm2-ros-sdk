# UR C: real official ROS communication

This is an unqualified source implementation. No Linux public build/test or new Stage A acceptance is claimed. The old623de8c3 VM is refused because its required successful measured-unwind record is missing. Use an actually qualified replacement and a fresh VM-owned live boundary/deployment; the example never creates admission or grants.

The genuine public C algorithm is example/platform/ros/portable/v0_1_0/joint_step/main.c. Xmake builds that source with the installed SDK. Execution requires the complete4449-byte C0 artifact c0d886e8... and its public source pins, then requires its actual result/fresh-state assertions inside Wasm. A different build is not called the same frozen artifact. Native code here is limited to the VM-owned restricted Host and authentic official Jazzy UR5e GenericSystem/JTC environment. The Python driver only launches, records actual processes/images and verifies existing runtime evidence; it has no native ROS client, observer, planner, goal publisher or fabricated feedback.

The public target remains ur-stage-a-joint-step; its output basename is explicitly portable-joint-step-v0-1-0, producing portable-joint-step-v0-1-0.wasm. The linker records this basename in the Wasm name section. SDK10's separate R25 public build reproduced the canonical 4449-byte C0 with that name; this UR source change still requires its own real public build and SHA check. The VM assembler must validate this artifact filename separately from the retained target identity. Historical R418 source/manifests are preserved; current source version is ur-official-communication-r428.

From this directory with UWVM_ROS_SDK_ROOT naming the installed SDK:

    xmake
    xmake test

The default full selection requires four named cases: permission denial before any endpoint, permitted real ROS/result/fresh guest state, stale native generation rejected before submit, and a bounded owned-Host crash before submit. The last two use the same public C Wasm error path and actual restricted-Host protocol. The stale case presents an old complete adapter/grant binding to a newer restricted Host at the same endpoint; both digest and generation bindings differ, so it is not an isolated per-field generation-check test. Stale post-result feedback is a separate remaining requirement. Status110 for stale binding is the current native client's failed-bind transport result; status38 for a retained socket after Host death is its connect-unavailable result. The expected statuses are not alternatives accepted merely to turn a failure green. Current SDK01 complete_operation_case does not yet qualify these negative feedback profiles, so the full suite remains non-success until that existing shared consumer is implemented and actually qualified. The driver does not bypass it by writing completed records directly.

An explicitly selected two-case milestone may be built with xmake f --ur_stage_a_scope=smoke, followed by xmake and xmake test. It remains partial Stage A, with two required negative cases outstanding. qualification-scopes.json reports the limited scope. Full Stage B, all original vendor/model/mode/release/ABI/language/link/security/debug/update/performance/world-model rows and independent component isolation remain required.

UWVM_UR_STAGE_A_CONTEXT names a context-relative vendor data file inside the real readonly VM-owned execution context. context.template.json is deliberately not executable. The producer must supply the fresh namespace/endpoint directory, exact restricted Host, approved official launch and loaded images, and per-case readonly adapter/grant/provenance files. This is vendor deployment data consumed through SDK01 LiveBoundary.context_file, not a replacement common ABI or authority. The VM's actual caller identity and policy checks remain decisive. Dynamic policies/endpoints cannot be made executable by copying the template or by supplying a producer string.

No quarantined native SDK implementation is called. This new example does not restore the previous official_mock_joint_step candidate. Its restricted Host receives the C guest's request; its actual audited terminal and the VM's real state copies are verified through the shared SDK consumer. A standard mock controller establishes communication scope only, not physical dynamics or full vendor simulation.

components/ contains the new planner static library and separate planner/actuator Wasm source targets.
