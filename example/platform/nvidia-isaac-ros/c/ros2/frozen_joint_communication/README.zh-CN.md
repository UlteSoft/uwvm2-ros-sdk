# 冻结 Wasm 与官方 ROS 通信

公开通信场景尚未完成正式核验。
本例先使用官方 Jazzy GenericSystem/JTC 和两个配置关节完成 Stage A；
无需模型或渲染 GPU，也不证明 Isaac 硬件、物理仿真或完整客户端迁移。

在具备已核验 VM 准入、部署及官方依赖的 Linux SDK 环境中执行：

    xmake
    xmake test

算法继续使用原始 4449 字节冻结 Wasm。目标计算、请求、结果和新鲜状态
断言均在 Wasm 内；官方 ROS 程序提供外部环境，受限 host 属于 VM。
两个官方 ROS 可执行程序分别通过公共 Context.spawn 入口及执行后身份核验，
不再由 SDK 监督脚本自行派生。构建输出遵从 Xmake 与 SDK 公共产物布局，
不覆盖对象或依赖目录。源码构建保留原始 `portable-joint-step-v0-1-0`
输出名，使产物元数据也能复现完整冻结字节；构建与通信分别记录证据。
原生 CLI 只在 guest 反馈核验通过后作独立测试观察，不发送目标或替代
guest 回调，不调用任何已隔离的 SDK 观察器。

本通信路线四项场景均必需：权限拒绝、正常结果、过期引用/反馈拒绝、
断连超时。后两项仍缺 VM/SDK01 的真实契约，缺失时测试返回非成功。
独立组件内存/权限隔离仍是单独的必需后续验证，不阻塞第一条 CPU 通信
路线；全部十三组隔离要求保持不变。
当前单组件不等于 perception/planner/actuator 的独立内存与权限隔离；
后续必须使用独立实例和经过核验的 copy/snapshot 通道。

Stage B 全部官方机器人仿真、反向传感、同 SHA 跨厂商以及最终真实世界
模型与复杂多语言集成要求保持不变。
