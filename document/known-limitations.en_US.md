# Known qualification limits

No complete SDK release qualification is currently established. Read
[scene qualification](simulation-validation.en_US.md) before interpreting a platform, language,
example or historical passing receipt.

## Complete upstream tasks remain the primary requirement

No platform's complete original upstream robotics task is qualified here.
Every platform still requires preserved upstream source/commit/licenses, an
original-task behavior oracle, complete runtime dependencies and port patches,
real Wasm modules, one-command official deployment and actual VM boundary
negatives. The inspected ABB/FANUC/Yaskawa, RRBot, Fourier, UBTECH and Isaac Sim profiles
use the SDK generic C0 step. Unitree retains a generic sensor-byte digest; the
Kinova typed-feedback guest and PAL maintained Java String subset are additional
SDK applications. None establishes a preserved complete original upstream task
and port patch. A separate original Unitree Go2 stand application is now public

ordinary wasm32 build selected the real CRC archive and linked original task;
both actual products passed declaration/member byte checks. This scoped build
does not qualify full framework/dependency ports or official task execution.
UR/Trossen failure-only entries and the explicitly missing Doosan official-scene
entry remain required gaps.

The application/ROS layer must run in real Wasm: task decisions, ROS client
calls, callbacks and feedback processing cannot be native substitutes. Official
native drivers, virtual controllers, simulators, physics/rendering engines and
their base dependencies are permitted documented external environments. Their
Wasm port is not a prerequisite. Record roles, exact versions, licenses and
actual VM-mediated communication; the rule applies to open and closed source.
Only remaining native application/ROS task behavior is an unported gap. This
corrects the earlier blanket-native-component interpretation without rewriting

## Documentation and physical systems

Chinese and English files require semantic parity, including commands, failure
conditions and qualification scope. Having both filenames is insufficient.
Historical review dates and test counts do not describe the current boot.

Licenses, account access, manufacturer downloads or unavailable official models
can block a particular simulation. Record exact prerequisites without replacing
the environment with a mock. Even a successful official simulator run qualifies
only its pinned model/controller scenario. Physical robots, site safety and real
hardware have not been qualified by simulation; no physical operation is part
of this acceptance campaign.
