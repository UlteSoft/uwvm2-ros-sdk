# trossen / kotlin examples

Each directory is a standalone Xmake project:

- `example/platform/trossen/kotlin/ros1/ros1_noetic/joint_single_command` — `subscribe/interbotix_xs_msgs/JointSingleCommand`; noetic.
- `example/platform/trossen/kotlin/ros1/ros1_noetic/joint_group_command` — `subscribe/interbotix_xs_msgs/JointGroupCommand`; noetic.
- `example/platform/trossen/kotlin/ros1/ros1_noetic/joint_trajectory_command` — `subscribe/interbotix_xs_msgs/JointTrajectoryCommand`; noetic.
- `example/platform/trossen/kotlin/ros2/ros2_jazzy/joint_single_command` — `subscribe/interbotix_xs_msgs/msg/JointSingleCommand`; jazzy.
- `example/platform/trossen/kotlin/ros2/ros2_jazzy/joint_group_command` — `subscribe/interbotix_xs_msgs/msg/JointGroupCommand`; jazzy.
- `example/platform/trossen/kotlin/ros2/ros2_jazzy/joint_trajectory_command` — `subscribe/interbotix_xs_msgs/msg/JointTrajectoryCommand`; jazzy.

Grant one explicit topic-subscribe alias and let a native simulated peer publish the whole selected type. The application polls at most 250 times with twenty-millisecond idle pauses, decodes and reencodes every field, closes once, and prints canonical bytes plus independent primary/cleanup/RPC/length facts. Denied permissions and malformed wire remain real failures; a failed receive is never resized and replayed.

Check that the build emits exactly one `.wasm`, then use `xmake run` with manually supplied permissions. Acceptance records real x86_64 and QEMU AArch64 runtime/ELF identities, ROS1/ROS2 message/service/action contents, denied permissions, malformed wire, actual cgroup limits and cleanup results.
