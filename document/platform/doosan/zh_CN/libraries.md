# doosan 库集成状态

Wasm 共享模块及静态归档的生产者、消费者路线仍待公共 SDK 集成。
现有编解码应用只证明各自实际验收过的 binary 行为。声明一个构建目标
本身不能证明链接、预加载或原生 ROS 通信。

使用普通 Xmake 接口：`set_kind("binary")`、`set_kind("shared")`、
`set_kind("static")`，以及 `add_deps`、`add_links`、`add_linkdirs` 和
公开包含目录传播。公共 SDK 必须保留声明的 kind；本厂商 provider 会
保留它收到的 kind。若公共 dispatcher 提前改成 binary，必须先完成
公共契约修正，才能验收库路线。

| 请求的目标种类 | 必须产生的真实产物 | 当前库验收状态 |
| --- | --- | --- |
| binary | 一个可部署的应用 `.wasm` | 只按具体 binary 例子的证据确认 |
| shared | 独立构建且实际预加载的 `.wasm` | 待验收 |
| static | 包含可重定位 Wasm 对象并参与最终链接的 `.a` | 待验收 |

静态归档必须经过真实符号提取。共享模块必须符合实际 uwvm 加载器的
导入、导出契约；Core Wasm 预加载能力不能证明 LLVM PIC/dylink 支持。
解释语言的源码打包也不能证明静态归档 ABI 或动态 Wasm 互操作。

首个要求的组合由四个独立构建的模块组成。下表给出集成拓扑；可复现并
通过验收的四模块例子仍待完成。

| 加载后的身份 | 职责 | 手动权限契约 |
| --- | --- | --- |
| main | 协调标量结果的应用 | 不授予 ROS 权限 |
| io | 使用 WASI 流 I/O 的独立共享模块 | 选定的 WASI 流策略，不授予 ROS 权限 |
| algorithm | 独立计算模块 | 默认 WASI，不增加资源或 ROS 授权 |
| ros_comm | 与受控原生 peer 通信的独立模块 | 只有此确切加载身份获得选定的 ROS Single 授权 |

默认 WASI 仍有基本标准流权限，不能描述成零描述符权限。WASI、ROS
Single 目标必须先针对实际加载身份创建、绑定，再配置手动权限。
全局 ROS 授权不能证明模块局部隔离。运行器必须保留用户配置，不增加授权。

每条路线都需要分别证明同语言、跨语言生产者与消费者，实际 memory32、
memory64，以及 Linux x86 和 QEMU AArch64 执行。需要验证传递依赖、
归档符号提取、导入导出冲突、位宽或签名不匹配拒绝和模块生命周期。
指针偏移只对特定线性内存有意义；跨模块调用必须明确内存、完整范围和
借用期限，不能假定各模块独立内存中的 C 指针可以直接互传。

原生 ROS 验收必须记录 ros_comm 的正向通信，以及没有授权的 main、io、
algorithm 发起操作后被明确拒绝的结果，并完成清理。完成的例子必须同时
提供完整命令、不可变的原生类型身份、gateway 配置和四份部署模块。
这些验收产物仍待完成；本源码候选没有为任何请求语言声明库生产者或
消费者已验收。
