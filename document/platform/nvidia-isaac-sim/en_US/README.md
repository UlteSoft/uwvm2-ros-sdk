# Isaac Sim joint and clock interfaces

Preserve JointState header and complete name/position/velocity/effort arrays. The authored ClockControl protocol retains nonce, request sequence, original frame/phase and independent native cleanup status.

The selected source revisions and every configuration key are in `share/platform/nvidia-isaac-sim/provider.json`. The retained profile uses ROS 2 Jazzy, DDS or pure CPU values, a Wasm32/Wasm64 WASI Preview 1 command, and explicit source revision selection. The umbrella additionally requires `ros.vendor.component`. `ros.vendor.version` is an immutable source commit, not robot firmware. `ros.vendor.transport=cpu-value` selects codec-only examples; `dds` describes native communication.

Install this platform overlay together with the shared SDK and its single locked compiler/interpreter bundles. Set `UWVM_ROS_SDK_ROOT` to that installation. Every standalone example contains its own `xmake.lua`; `xmake` produces one `.wasm` inside `build`. Toolchain caches and intermediate native products stay outside deployment. Edit `set_arch("wasm32")` to `set_arch("wasm64")` only for a genuinely built and executed target route. Preview 2, threads and exception profiles require their own acceptance.

The three complete-value examples are `roundtrip`, `malformed_wire` and `stdin_record`. The umbrella names their selected component in each scenario. Roundtrip accepts an optional unsigned 32-bit seed and prints every actual canonical byte. Malformed-wire checks exact framing, destination preservation and insufficient-capacity refusal. Stdin-record accepts a complete canonical body, refuses an oversized/truncated/trailing value and reproduces every active byte. These are codec exercises; retained telemetry/native programs carry the separate ROS/GPU surfaces.

An encode succeeds only for the complete finite value. Strings use strict UTF-8 without NUL and explicit byte quotas. Arrays retain every element and declared order; an oversized value fails as a whole. C encode/decode commits only after full validation and rejects output/input overlap. Canonical identities describe the SDK codec, not a native ROS MD5/RIHS identity. Registering a native resource requires original generated TypeSupport, the exact original native root/component identity and an operator-supplied deployment.

Errors remain independent: 11 means a caller-driven operation has no value yet, 13 is permission denial, 22 is invalid framing/value/storage, 90 is an exceeded finite quota, 95 is a missing admitted feature/domain, and 110 is a finite deadline. A native service's typed failure is separate from transport/codec/ACK/cleanup errors. No uncertain service effect is automatically retried. Do not truncate covariance, images, joint arrays, tensor horizons or typed failure fields to report success.

`xmake run` uses the installed `uwvm2-ros` selected by `UWVM_ROS_RUNTIME` and manually supplied `ros.sdk.run_argv`. No capability is added. A deployment must explicitly configure native ROS resources, policies, aliases, exact native identities and finite quotas. Test fixtures use loopback/private ROS graphs. Physical robot actuation is outside this delivery's test scope.

GPU execution is a separate native requirement. GR00T requires its pinned real SDK, offline model/processor weights, NumPy/PyTorch/transformers/CUDA and an admitted device. Isaac ROS requires the actual detector/backend and input buffer ownership/synchronization. Isaac Sim requires the actual Kit/USD scene, graph, physics and renderer. A native ROS peer, codec roundtrip or denied host invocation does not qualify training, inference, rendering or simulation.

Run [`run_container.py` in uwvm2-ros](https://github.com/UlteSoft/uwvm2-ros/blob/main/test/0073.ros-tests/sdk/tools/aarch64/run_container.py) on Linux with the common flock and a complete transferred work folder. Its 64 GiB/zero-swap container invokes `accept.py` using exact native asset and Wasm hashes. It records actual ELF machine numbers, memory flags, QEMU version/arguments, native message/service/action witnesses and owned cleanup. ARM runtime execution under QEMU and source compilation by an ARM-host compiler are separate acceptance rows. Consult the external delivery coverage receipts for actual built/executed states; source presence is not completion.

The required ordinary Xmake targets are `set_kind("binary")`, `set_kind("shared")` and `set_kind("static")`, with standard `add_deps`, `add_links`, `add_linkdirs` and public includes. The present platform application examples do not qualify shared/static producer or consumer support. A shared deployment needs each real Wasm library plus explicit preload names; a static archive contains relocatable Wasm objects and must undergo actual archive-symbol extraction. Each language, memory width and producer/consumer combination needs its own execution result.

The required module example has `main`, `io`, `algorithm` and `ros_comm`. Only `ros_comm` receives manual ROS Single authority bound to its loaded module identity. Default WASI retains basic standard-stream rights; algorithm receives no additional resource or ROS grants. The common loader/build-kind/cross-module caller contract must be qualified before claiming this flow. Native positive observations and denied operations from ungranted modules are required; `xmake run` preserves the exact submitted configuration.
