# realman: retained complete helper workflows

`c/state.h` retains all five original source profiles. `uwvm_realman_poll_status` validates and commits the complete ArmState/Armstate value. `uwvm_realman_publish_joint` validates and serializes every original selected JointPos/Jointpos command field once; the caller supplies exact controller/mode, limits, original units and authority. `cpp/state.hpp` exposes borrowed `Reader.poll` and `Publisher.publish`; each owns scratch only.

`js/get_arm_state.mjs` exports `ArmStateQuery`: `onTime`, `onReady`, `onVersion`, `onArmState`, `onEulerState`, `onForce`, `close`. It retains original software-version, quaternion/Euler state and raw/sensor-zero/work-zero/tool-zero force workflows. Explicit nondecreasing full-width ROS time controls readiness and publication waits; there is no wall-clock fallback. Complete original values are validated before formatting and callbacks preserve actual output/publication status. The retained `share/platform/realman/query-core` domain is the original zero-byte ROS1 `std_msgs/Empty` topic-request value. It is not an invented service; native registration/delivery remains independently required.

All helpers retain caller-owned native capabilities. Use the exact source profile and complete generated record/interface headers. Preserve primary operation, whole-value decoding, application response and one independent close as distinct facts. Fatal process/trap cleanup and physical controller completion are outside local facade state. Genuine x86 native ROS and QEMU ARM evidence is required separately; these source/manuals do not certify workflow or hardware parity.
