# 附加便携能力源码，v0.2.0 预览

这两个算法目前只有源码；尚无生成的 Wasm、VM 主机实现、原生 ROS 结果或官方仿真验收。
冻结描述中的可用性字段记录源码封存时的状态，后续产物和执行结果必须用独立凭据发布。

`planar_goal` 使用逻辑别名 `navigation`，根据实际返回的位置计算一次有界的 x 方向位移，
提交平面位姿目标，等待原生终态并检查新的位姿。主机必须实现独立的
`planar.pose.goal.v1`，由外部适配文档确定坐标系、地图/里程计、原生 action 和仿真实例。
该算法不实现电机、平衡或步态控制；原生目标被接受并不表示执行完成。

`sensor_digest` 只使用逻辑别名 `sensor` 的描述、读取和关闭权限，验证一帧 mono8/RGB8
数据，然后在 Wasm 内对实际载荷（包括行填充）计算 FNV-1a-32。必须独立保留对应的
原生仿真采样，证明同一份数据进入了正在执行的 Wasm。FNV 仅用作该算法的正确性核对，
不提供认证、目标检测、标定、深度或 IMU 处理。

两个算法复用 `include/platform/ros/portable/v0_1_0/abi.h` 中的通用七调用 ABI 声明，
使用 `share/platform/ros/portable/v0.2.0/wire.json` 中各自独立的记录类型。
只读传感器程序不必导入未使用的提交和等待函数。不支持某能力族时主机必须拒绝，
不能将其静默改写为关节命令。

在通过准入的 Linux 工作进程中，设置 `UWVM_ROS_SDK_ROOT` 为其精确暂存 SDK，
进入所选示例目录，运行 `xmake f -y -c -a wasm32`，再运行 `xmake -vD -j2`。
这只是现有 C/WASI 路径的复现命令，尚未作为本版本的实际结果执行；它们不启动仿真器，
也不选择机器人平台。

每个算法只生成并冻结一次，保留完整 SHA256、编译器和源码输入，之后在所有适用平台上
复用完全相同的字节。适配、权限、资源名称、单位换算和坐标变换均放在 Wasm 外。
从同一源码重新编译不构成同字节复用证据。所有官方适用仿真模式、ROS 发行版及 ABI
都需要各自的真实执行记录和正确性核对；禁止驱动物理机器人。

`share/platform/ros/portable/capability-families.json` 还记录了机械臂笛卡尔控制、夹爪、
力矩、足式运动、激光雷达、IMU 和视觉等后续语义工作。该文件只是部分能力清单，
并非完整的官方机器人/仿真模式审计。缺少主机实现或已安装依赖应记录为阻塞，不能据此
标记为不适用。
