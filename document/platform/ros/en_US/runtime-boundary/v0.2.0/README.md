# Live runtime boundary v0.2 candidate

The consumer matches the fixed VM public-live-boundary-v2-r5 producer field map.
It is a source candidate: Linux syntax, new interruption/benign, public joint and
the12 live rejection cases have not been executed for this SDK source.

The installed approved-producers.json contains one exact fixed-input,
current-boot qualification source approval. production_approved is empty.
Source approval permits only otherwise admitted bounded qualification and never
means a public product, ROS communication or runtime boundary passed.

The source approval binds descriptor97defd65..., original archive9d7bc623...,
36 exact packet/control source files,1346 actual root-owned runtime files and
17 exact SDK consumer inputs on boot4a4ef5a2-2ae7-4680-9e31-7dc620a8033f.
The complete hashes and rows are stored in the SDK-owned approval record.
Changing an approved consumer file requires a new reviewed record and a new
whole subject qualification. No source-review JSON or candidate descriptor can
create approval itself.

V2 requires admission format uwvm-sdk-simulation-admission-v2, protocol
uwvm-sdk-live-boundary-v2 and producer uwvm2-ros/guardian-v2. Selection uses
admission.producer_descriptor_sha256. The original descriptor, source/runtime
manifests, whole launch contract and role argv/source-FD subcontracts are under
producers/vm-closed-boundary-r5. They are copied from the hash-verified original
archive without altering their bytes. The consumer also matches the
producer-published copies in the actual readonly context.

Actual controller and guardian must be distinct live PID/birth pairs. Their
whole source closure and metadata must remain on the actual original O_RDONLY
FDs, without O_PATH, with kernel F_GET_SEALS exactly15. Kernel argv must execute
the pinned role_bootstrap.py FD under the exact interpreter with -I -S -B.
Actual launch FD, logical role argv, inherited role FDs, environment, parent,
source bytes, runtime FDs, current executable and loaded map device/inode are
independently checked. Claimed booleans do not replace these kernel reads.

The host profile requires all four UID/GID slots1000, exact supplementary
groups from the fixed runtime manifest, zero inheritable/permitted/effective/
ambient capabilities, CapBnd000001ffffffffff, NNP0 and seccomp0. It applies only
to these exact approved closed roles. Every SDK/native/VM/application helper
keeps the existing strict all-capabilities-zero, UID/GID1000, NNP1/seccomp2
profile. Legacy v1 keeps its exact original security checks.

The sealed startup context fixes nonce, boot, whole subject packet, paths,
providers, requester and proof inputs. Only lease_owner can change, and it must
name the actual acquiring controller and existing canonical inode. The guardian
must actually be that controller's child and retain its inherited canonical FD.

Before product execution, the same exact current subject must have its own two
real interruptions, independent original/physical-retirement review, and bounded
benign successor. The SDK checks the copied original proof and the same-subject
benign/hash/raw bindings from the actual sealed startup context. The fixed R3
management source is a separate management boundary: its admitted requester/RPC
clients do not acquire an approved producer role or an application capability.

Actual shared and actor/control leaves remain under the pinned readonly cgroup2
ancestor with64GiB memory.max, zero swap, exact cpuset and nondelegated control
files. The namespace join opens the shared-directory FD, identifies its actual
mount root using fdinfo mnt_id, subtracts that literal root from the kernel
reader-relative membership, and opens one exact direct leaf beneath the FD.
Both device and inode must match. Parent components are not traversed and host
membership text is never rewritten or compared for cross-namespace equality.
See [Linux cgroup_namespaces(7)](https://man7.org/linux/man-pages/man7/cgroup_namespaces.7.html).

V2 atomic guardian/direct observation formats are v2. Generations must match,
counters must not regress, and every actual source/image/lease observation must
be <=500ms old. The SDK separately checks actual current canonical source FDs
and kernel WRITE FLOCK for both controller and guardian. Every earlier proof,
source, budget, freshness and physical-retirement requirement remains mandatory.

Application write access to the host context through a host-proc alias must be
denied, in addition to the direct context mount being readonly. This is a
required consumer gate and required live rejection case; its actual result for
the candidate has not been measured. Qualification must preserve any failure.
No source flag, edited receipt or private case may turn it into a public pass.

The12 required live rejection families remain recorded as NOT_RUN in
required-negatives.json. Product approval can be produced only after actual
original public xmake/configure/build/xmake test positive joint cases and those
independent rejections, with original raw evidence and exact current inputs.
