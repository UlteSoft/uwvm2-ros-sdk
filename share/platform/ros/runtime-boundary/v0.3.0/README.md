# Kernel witness v3 candidate

This is an opt-in consumer contract. There is no approved witness, issuer, new producer, execution admission or runtime pass. The v2 direct-proc consumer remains byte-for-byte unchanged. A new matched input subject must be qualified before running this candidate.

The original public failure is proven: the application under docker-default could read the published files but could not open the unconfined controller's actual source fdinfo. The retained FD existed and was sealed/read-only. R838 is superseded for repeating that failure; both original failures and the new raw traceback remain preserved.

V3 delegates protected kernel collection to an explicitly approved, unconfined UID1000 read-only witness with capabilities including bounding set zero, NNP1/seccomp2 and an ephemeral key created after an irreversible nondumpable bootstrap. The application retains its current security profile. The existing OS-root resource bootstrap is an explicit enrollment authority; its unchanged authorized profile must actually support issuance. There is no new root service, permission exception or implicit trust in a producer key. The installed witness registry starts empty and defaults to DENY.

The root-owned sealed enrollment binds a complete measured issuer/witness closure and the current job. Every guard generates a new challenge. A fresh PSS signature binds live controller/guardian PID/birth/exe, sources, actual used runtime and maps, context, namespaces/cgroup and inherited lease. The consumer separately reads immutable passed objects, live kernel births/status/cgroups, actual narrow procfs lease-fdinfo readers and existing global locks. Mutable records, copied observations and descriptors alone cannot authorize.

FD passing requires care. SCM_RIGHTS shares the sender's open file description. Sending the original read-only canonical lease FD would let the recipient alter the flock. Therefore that OFD never crosses the boundary. Mutable host/context file descriptors are also forbidden because a read-only descriptor can still expose a reopenable inode. Only sealed source/metadata, root-owned nonwritable runtime files and narrow actual procfs fdinfo readers are allowed. The witness opens independent descriptions and measures kcmp plus full identity/type/lifetime constraints. kcmp alone is not a stable snapshot; approved retained role FDs must never be replaced, and pre/post identity checks remain mandatory.

The complete available runtime input inventory and the actual retained/loaded runtime closure are distinct. Every available file is provisioned and hash-qualified. Each role's complete current used subset is retained and measured; all file maps and imports must come from the approved closure. The existing512 FD ceiling is not a requirement to retain all1346 available runtime inputs simultaneously.

WIRE_SCHEMA.json specifies all required transport and measurement fields. bootstrap-state-machine.json specifies the one-way root/key/lock lifecycle. required-negatives.json preserves the original12 live refusal categories and lists additional Linux wire/crypto/kernel conformance work. Consumer Python source is an additional exact normative constraint. Inner role execution contracts use the existing v2 schema shape; outer admission, producer and atomic lease observations use v3. New source/descriptor/SDK pins are always required.

No SDK code was imported, parsed, compiled, syntax checked or executed on macOS. Source/data edits and metadata hashes are the only local operations. Source review cannot establish LSM, procfs FD-transfer, kcmp, crypto-provider or timing compatibility. Those are explicit Linux probe prerequisites; failed/unsupported checks block without privilege fallback. The SDK consumer RSA-PSS implementation also needs independent OpenSSL conformance vectors before any acceptance.

Primary interface references: [Unix sockets and SCM_RIGHTS](https://man7.org/linux/man-pages/man7/unix.7.html), [kcmp and its ptrace checks/snapshot limits](https://man7.org/linux/man-pages/man2/kcmp.2.html), [nondumpable processes](https://man7.org/linux/man-pages/man2/PR_SET_DUMPABLE.2const.html), [memfd sealing](https://man7.org/linux/man-pages/man2/memfd_create.2.html), [RSA-PSS specification](https://www.rfc-editor.org/rfc/rfc8017.html), [Linux procfs](https://docs.kernel.org/filesystems/proc.html). They describe interfaces; the installed host's original kernel evidence decides compatibility.
