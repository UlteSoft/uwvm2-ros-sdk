# Kernel-object consumer proposal 0.4.0

This is a frozen conditional design, not a registered protocol or working consumer. It authorizes no execution. R840's OS-root enrollment proposal is withdrawn: the existing root bootstrap also has capabilities0, UID0 does not establish access to a nondumpable target, and the current task forbids a root observation/signing proxy. The preserved R840 source and failures remain available for review.

The only direction retained here is direct SDK validation of tightly scoped actual read-only kernel objects under unchanged existing profiles. A nonroot courier would only move handles. Its UID, source claim, reply time, key, nonce or JSON would not attest to any fact. No signing witness or new trust root is introduced. Actual kernel relations must replace every required protected read, including current executable, full retained source/runtime census, namespaces/cgroup and inherited canonical lease. Missing relations mean DENY.

Passing a procfs handle is not sufficient evidence. In illustrative Linux v6.12 source, a maps reader refers to an mm selected at open and seq_file has cached state. A surviving shared mm, old executable object or pre-read buffer must not masquerade as the target's current image. These are questions for the installed kernel, with real exec/FD-swap/exit/cached-read probes. A successful ordinary transfer alone cannot establish the protocol. See required-kernel-evidence.json for exact minimum questions and primary links.

There is also a concrete budget issue: each role in the original R5 failure has36 source FDs,121 used runtime FDs,31 additional sealed import-source FDs,3 metadata FDs,1 launch FD and1 distinct executable FD:193 original FD numbers. Two roles need386 object occurrences; a separate current fdinfo reader per original FD plus2 lease readers totals774 handles. Even payload deduplication by actual device/inode leaves263 objects+386 fdinfo+2 lease=651 handles. The existing512 limit cannot carry that set in one frame. A bounded streaming design must preserve complete census, current generation, fresh deadlines and peak-FD limits; dropping interpreted imports or trusting row counts is forbidden.

The current public consumer explicitly rejects admission-v3. Admission-v4 is not registered. V2's direct checks remain unchanged. No new C ABI, Wasm import, ROS permission or feedback schema is introduced. The narrow blocked boundary is before real guest/ROS dispatch; finite Java/compiler output does not qualify that entry. SDK05's26-assertion auxiliary contract and SDK09 service-r6 stay queued separately from real business and full simulation counts.

All current-boot own proof/benign/retirement,64GiB/swap0, full-lifetime canonical lease, original capacity floors and smallest UR positive plus12 real refusals remain mandatory. No Mac SDK/VM import, syntax, AST, build, compile, test or run has occurred. This source/design work and its metadata hashes are not runtime qualification.
